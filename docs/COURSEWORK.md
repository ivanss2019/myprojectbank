# Курсовая работа — анализ транзакций

Реализованы задачи из трёх категорий; объём расширен по критериям оценки:

| Категория | Реализация | Основной модуль |
| --- | --- | --- |
| Веб-страницы | Главная: приветствие, карты, кешбэк, топ-5, валюты, акции | `src/views.py` |
| Веб-страницы | События: расходы, поступления, топ-7, диапазоны W/M/Y/ALL | `src/views.py` |
| Сервисы | Простой поиск, поиск телефонов, выгодные категории кешбэка | `src/services.py` |
| Отчёты | Траты по категории за три месяца с сохранением Excel | `src/reports.py` |

Инвесткопилка, поиск переводов физлицам и два других варианта отчётов не входят
в выбранный объём: их нет в присланных критериях, а исходное условие требует
минимум по одной задаче в каждой категории.

## Структура и запуск

- `src/analysis_utils.py` — чтение Excel, настроек и подготовка данных. Старый
  банковский `src/utils.py` сохранён для совместимости с предыдущими заданиями.
- `src/market_data.py` — запросы к внешним API через `requests`.
- `src/views.py` — формирование JSON главной страницы из переданных данных.
- `src/services.py` — функциональный поиск (`filter`, `lambda`, `any`).
- `src/reports.py` — расчёт отчёта и декоратор сохранения.
- `src/main.py` — связывает чтение файлов с обработкой, предоставляет команды.
- `tests/coursework/` — тесты курсовой, включая проверки на исходном Excel.
- `user_settings.json` — список валют и тикеров акций.
- `.env.template` — шаблон переменных окружения.
- `reports/` — создаваемые отчёты (исключены из Git).

Установка в существующее окружение Poetry:

```bash
poetry install --with lint,test
```

Команды из корня репозитория:

```bash
# JSON главной страницы. Время обязательно заключить в кавычки.
poetry run python -m src.main home "2021-12-31 23:59:59"

# Поиск по всему файлу
poetry run python -m src.main search "магнит"

# Excel за три месяца по выбранной категории
poetry run python -m src.main report "Супермаркеты" --date 2021-12-31

# Другой входной файл и имя результата
poetry run python -m src.main --file data/operations.xlsx report "Транспорт" \
  --date 2021-12-31 --output reports/transport.xlsx

# Другой файл настроек
poetry run python -m src.main home "2021-12-31 23:59:59" \
  --settings user_settings.json

poetry run python -m src.main --help
```

JSON печатается в stdout, диагностические сообщения — в stderr, поэтому вывод
можно перенаправлять в файл. При ошибке входного файла или даты команда завершается
с кодом 1 и понятным сообщением. Пути по умолчанию вычисляются относительно проекта;
переданные относительные пути — относительно текущего рабочего каталога.

## Данные задания

[Исходная таблица operations.xlsx](https://docs.google.com/spreadsheets/d/1yXnr282zAMcTkEhIwZFaJlPJvAeZIwvB/edit)
экспортирована в XLSX без изменения данных. Содержит 6 705 операций с 01.01.2018
по 31.12.2021 и 15 столбцов. В тексте задания файл назван `operations.xls`,
но предоставленная таблица — `operations.xlsx`; для неё используется установленный
`openpyxl`. Для старого бинарного `.xls` pandas отдельно требует `xlrd`, который
не входит в текущие зависимости: такой файл нужно предварительно сохранить как XLSX.

Чтение файлов отделено от бизнес-логики. `home_page`, `build_category_report`
и `simple_search` получают данные напрямую, что позволяет тестировать их без Excel
и заменить источник данных в будущем. Исходный датафрейм не изменяется.

## Главная страница

```python
from src.main import main

response_json = main("2021-12-31 23:59:59")
```

Для работы без чтения файлов:

```python
from src.analysis_utils import read_excel_transactions, load_user_settings
from src.views import home_page

transactions = read_excel_transactions("data/operations.xlsx")
settings = load_user_settings("user_settings.json")
response_json = home_page("2021-12-31 23:59:59", transactions, settings)
```

Формат ответа: `greeting`, `cards`, `top_transactions`, `currency_rates`,
`stock_prices` — как в задании.

Принятые правила расчёта (для сверки с критериями наставника):

- Период: с первого дня месяца 00:00:00 по заданное время **включительно**.
  Фильтрация идёт по «Дате операции», не по дате платежа.
- Приветствие зависит от текущего локального времени запуска, а не исторической
  даты анализа: ночь 00–05, утро 06–11, день 12–17, вечер 18–22; с 23:00 снова ночь.
  Для воспроизводимых тестов можно передать `now` в `home_page` и `get_greeting`.
- `FAILED` исключаются из финансовых расчётов. Если столбца «Статус» нет,
  переданный набор считается состоящим из успешных операций.
- Страница показывает платежи в RUB/RUR. В исходной таблице есть также CNY:
  они исключаются, чтобы не складывать рубли и юани. Количество исключений
  логируется. Если столбца валюты нет, суммы считаются рублёвыми.
- Расходы — модуль отрицательных сумм платежа. Поступления и возвраты не уменьшают
  расходы. В ответе расходы по картам положительные, округляются до копеек.
- Кешбэк — 1% расходов, с округлением до копеек по `ROUND_HALF_UP`.
  Например, расходы 7,94 ₽ дают 0,08 ₽. Поле «Кэшбэк» из файла здесь не используется.
- Последние четыре цифры карты сохраняются строкой (включая ведущие нули).
  Операции без номера карты не включаются в карточные итоги, но могут попасть в топ.
  Карта с одними поступлениями получает нулевые расходы и кешбэк.
- Топ-5 сортируется по значению «Суммы платежа» по убыванию; сохраняет исходный знак
  суммы. При равенстве порядок соответствует исходной таблице. В топе есть и
  расходы, и поступления. Категория/описание без значения заменяются пустой строкой.
- Курсы и цены акций — последние доступные на момент запроса, не исторические.

## Внешние API и настройки

В `user_settings.json`:

```json
{
  "user_currencies": ["USD", "EUR"],
  "user_stocks": ["AAPL", "AMZN", "GOOGL", "MSFT", "TSLA"]
}
```

Курсы валют: [XML API Банка России](https://www.cbr.ru/development/sxml/),
`https://www.cbr.ru/scripts/XML_daily.asp`. Ключ не нужен. Значение делится
на номинал: возвращаются рубли за **одну единицу** валюты.

Цены акций: [Alpha Vantage GLOBAL_QUOTE](https://www.alphavantage.co/documentation/#latestprice),
`https://www.alphavantage.co/query`. Цены выбранных американских акций — в USD.
Доступность и частота обновления зависят от тарифа провайдера; это не обещание
котировок в реальном времени. Список акций задаётся пользователем, принадлежность
к S&P 500 автоматически не проверяется.

Добавьте в существующий `.env` (не публикуйте ключ):

```text
ALPHA_VANTAGE_API_KEY=ваш_ключ
```

При первом создании `.env` можно скопировать `.env.template`. Существующий файл
перезаписывать не требуется. Курсовая загружает `.env` в точке входа `main()`;
модули расчётов не выполняют сетевых запросов при импорте.

Запросы имеют таймаут 10 секунд, HTTP-ошибки проверяются. Ошибки связи, лимиты API,
неверные ответы и отсутствующий ключ логируются; соответствующее `rate`/`price`
становится `null`. Ноль или выдуманные значения не подставляются. Успешные
котировки сохраняются, даже если запрос к другому тикеру не удался. API-ключи
и URL с ними не попадают в логи. Для полностью автономного запуска можно указать
пустые списки валют и акций в отдельном файле настроек.

## Простой поиск

```python
from src.analysis_utils import dataframe_records, read_excel_transactions
from src.services import simple_search

transactions = dataframe_records(read_excel_transactions("data/operations.xlsx"))
result_json = simple_search("магнит", transactions)
```

Поиск ведётся по описанию **или** категории, без учёта регистра, по всей истории,
включая неуспешные операции. Запрос — буквальная подстрока: специальные символы
регулярных выражений не имеют особого значения. Пустой запрос возвращает весь
список, отсутствие совпадений — `[]`. Исходные записи не изменяются.
`dataframe_records` превращает отсутствующие значения Excel в JSON `null`.

## Отчёт и декоратор

```python
from src.reports import build_category_report, save_report, spending_by_category

# Сохраняет reports/spending_by_category.xlsx и возвращает DataFrame
report = spending_by_category(transactions_df, "Супермаркеты", "2021-12-31")

# Чистый расчёт без записи файла
report = build_category_report(transactions_df, "Супермаркеты", "2021-12-31")

# Декоратор с параметром имени файла
custom_report = save_report(filename="reports/custom.xlsx")(build_category_report)
report = custom_report(transactions_df, "Транспорт", "2021-12-31")
```

Декоратор поддерживает `@save_report`, `@save_report()` и
`@save_report(filename="reports/custom.xlsx")`, сохраняет метаданные функции
через `functools.wraps` и возвращает её результат.

Дата отчёта передаётся как `YYYY-MM-DD`; без даты используется текущая дата.
Период начинается ровно за **три календарных месяца**, а не 90 дней, и включает
весь последний день. Например, 20.05.2020 означает 20.02.2020–20.05.2020;
31.05.2020 — 29.02.2020–31.05.2020. Категория сравнивается точно.
Отбираются только успешные отрицательные платежи. Отчёт сохраняет исходные
столбцы и валюты, не суммируя разноимённые валюты. Пустой результат создаёт Excel
с заголовками; одноимённый файл при следующем запуске перезаписывается.

## Дополнения по критериям оценки

```bash
poetry run python -m src.main events 2021-12-31 --range M
poetry run python -m src.main phones
poetry run python -m src.main cashback 2021 12 --rate 5
```

### События

`events_page(date, transactions, settings, date_range="M")` возвращает JSON:
`expenses` (расходы), `income` (поступления), `currency_rates`, `stock_prices`.
В блоках денежных итогов `total_amount` — общая сумма, `main` — список пар
`category`/`amount`. У расходов дополнительно есть `transfers_and_cash`.

Начало диапазона: W — понедельник текущей недели, M — первое число месяца,
Y — 1 января, ALL — начало истории. Конец — указанный день включительно.
Будущие операции не учитываются. Используются успешные рублёвые платежи.
Расходы агрегируются как положительные суммы; переводы и наличные вынесены
в отдельный список. Основные расходы: первые 7 категорий по убыванию,
остальные суммируются в «Остальное». Поступления сгруппированы по всем категориям.
Округление до целых рублей выполняется после суммирования, по ROUND_HALF_UP.
Общий итог округляется независимо от сумм отдельных категорий, поэтому возможна
разница на несколько рублей при сложении уже округлённых значений.

### Повышенный кешбэк

`profitable_cashback_categories(data, year, month, cashback_rate=5.0)` возвращает
JSON-объект «категория: потенциальный кешбэк», отсортированный по убыванию выгоды.
Выводятся все найденные категории: на исходной таблице их больше трёх.
Считаются успешные рублёвые расходы за выбранный календарный месяц; переводы,
наличные и поступления исключены. Используются `reduce` и `sorted`.

В условии нет ставки повышенного кешбэка, поэтому **5% — явно принятое допущение**,
ставка задаётся аргументом или `--rate`. Это оценка потенциального кешбэка,
а не суммирование фактического поля «Кэшбэк» и не воспроизведение тарифов банка.
Округление до копеек выполняется после суммирования трат категории.

### Телефоны

`phone_search(transactions)` возвращает JSON со всеми совпавшими транзакциями.
Регулярное выражение поддерживает российские мобильные номера с кодом 9xx:
`+7 (900) 000-00-00`, `89000000000`, `+7 995 555-55-55`, `7-981-333-44-55`.
Поддерживаются пробелы, скобки и дефисы. Исключаются короткие/длинные номера,
городские коды и совпадения внутри длинных идентификаторов. При двух номерах
в одном описании запись возвращается один раз. Поиск ведётся по всей истории.

### Ограничения полноты данных

Требования «хотя бы одна карта», «ровно 5 транзакций», «не менее 3 категорий»
проверены на предоставленном файле за декабрь 2021 года. Если выбранный период
содержит меньше данных, программа возвращает доступные записи, не дублирует их
и не создаёт вымышленные карты, операции или категории.

Требования положительных курсов и цен проверены тестами с успешными ответами API.
Для проверки реальных значений нужен сетевой доступ и ключ Alpha Vantage.
При недоступности API значения `null` — честное обозначение отсутствия данных;
этот режим не считается выполнением критерия «float > 0».
